# Сетевая оптимизация VOLNA

Воспроизведение остаётся в плеере Яндекс Музыки по выбору пользователя. Изменения относятся к скачиванию; собственный плеер, RAM-буфер воспроизведения, seek-прокси и постоянный аудиокэш на 1–2 ГБ не добавлялись.

## Реализация

- API: единая очередь в background, старт запросов с адаптивным шагом от 75 мс (при 429 шаг удваивается до 350 мс и затем плавно снижается), максимум 6 параллельных резолвов, отмена ожидающих запросов. Общий ограничитель используется также для метаданных, списка коллекции, форматов и текстов.
- Приоритетный путь — GET get-file-info с существующей HMAC-SHA256 подписью web-клиента и текущим разрешённым входом. Старый download-info/XML оставлен как совместимый резерв. Массив urls сохраняется и проверяется по разрешённым хостам.
- URL-кэш существует только в RAM текущей задачи: TTL до 5 минут, раннее исключение ссылок с expires, до 200 записей, подготовка следующих 16 треков. Отклонённая CDN-ссылка запрашивается заново один раз. Ошибки резолва кратко запоминаются, чтобы prefetch не дублировал неудачный запрос.
- CDN: один MediaClient и общий лимит 24 одновременно занятых запроса, включая зеркала и сегменты. В интерфейсе выбираются 1–16 потоков; новый профиль использует 12, прежние настройки сохраняются.
- Дополнительное зеркало для треков запускается через 150 мс ожидания заголовков при свободном слоте; проигравший запрос отменяется. При ошибке зеркала доступно следующее без повторного API-резолва. 429 не обходит другие зеркала: сначала выдерживается Retry-After.
- GET-запросы API имеют ограниченные повторные попытки; CDN — до 4 попыток с растущей задержкой и jitter. Retry-After поддерживает секунды и HTTP-date, ожидание ограничено 2 минутами. Отсутствие данных 45 секунд вызывает повтор; общая длительность активной передачи не ограничена 3 минутами.
- Дозагрузка использует Range и If-Range с сильным ETag либо Last-Modified. Проверяются Content-Range, общий размер и идентичность представления. Ответ 200 на If-Range перезапускает файл, неправильный/сжатый диапазон не приклеивается к старым байтам. Без валидатора загрузка безопасно начинается заново.
- Отдельный выбранный трек от 2 МиБ может загружаться до восьми диапазонов после проверки поддержки Range (при не менее 512 КиБ на сегмент). При несовместимом сервере применяется обычный путь. Пул сегментов входит в общий лимит 24, а не добавляет соединения сверх лимита.
- В «Оригинале» предпочитаются AAC-MP4, HE-AAC-MP4, затем MP3. Явно выбранный формат сохраняется. Используется разрешённый raw-транспорт; encraw/AES/DRM-расшифровка не реализованы и не выдаются за поддерживаемые.
- Добавлены агрегированная скорость, полученные байты и приблизительное оставшееся время. Неизвестный размер и этап сохранения ZIP показываются отдельно. Счётчики не путают сетевые байты с размером ID3/WAV после обработки.
- Исправлены гонка повторного использования сброшенной ссылки, зависание polling после быстрого завершения, неверная надпись для частичного результата, скрытые ошибки пропущенных песен и лишние операции очистки. При ошибке записи ZIP активные передачи останавливаются. Старые завершённые записи истории могут освобождаться при переполнении storage; активные и повторяемые задачи сохраняются.

## Ограничения браузера и границы результата

HTTP/2, HTTP/3, TCP и фактический пул соединений выбирает Chrome. RequestInit не предоставляет TCP_NODELAY или выбор HTTP-версии. Accept-Encoding, Connection и Keep-Alive нельзя устанавливать обычным Fetch; вместо неподдерживаемых заголовков проверяется представление ответа. Для заранее известных CDN-хостов используются браузерные preconnect-подсказки, без лишних HEAD-запросов к API.

Нельзя гарантировать отсутствие 429 при неизвестных серверных лимитах, параллельных клиентах аккаунта и изменениях сервиса. Ограничитель и backoff уменьшают риск и корректно обрабатывают отказ. TTFA <100 мс не измерялось и не обещается для оставленного плеера Яндекса; 180–210 Мбит/с реального Yandex CDN также не измерялись.

## Проверка

- 112 тестов Vitest: очереди API/CDN, Retry-After, отмена, URL-кэш, 8 потоков, Range/If-Range, смена представления, четыре сегмента, лимит ресурсов, статистика, ошибки, ZIP64, файлы и интерфейс.
- Изолированный Chrome и собственный HTTP-сервер: обрыв после 512 КиБ с продолжением bytes=524288-, переключение зеркала, четыре диапазона и пакет 10 файлов. Все SHA-256 совпали. Тест передал 80 МиБ в пакете через loopback; это не замер скорости Яндекс Музыки. Подробности: artifacts/network-browser-validation.json.
- 22 браузерные UI-проверки плюс 5 проверок File System Access/IndexedDB. В них проверены скорость, ETA, размер, 8 потоков, сообщения о сети, темы и отсутствие горизонтального переполнения.
- npm audit: известных уязвимостей не найдено. Установленная копия Chrome автоматически не перезагружалась; готовая сборка находится в dist.
