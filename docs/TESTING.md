# Фактические проверки

Дата: 14 ноября 2026. Среда: Windows, Node.js, Chrome, Vitest, Playwright CLI.

## Автоматизированные проверки

112 тестов Vitest: домены, имена файлов и Unicode, кодеки и контейнеры, WAV PCM, ID3, Vorbis comments, FLAC-MP4 с сохранением сэмплов, web-подпись, preview/encrypted, XML, параллельность, SPA и cleanup, ZIP с распаковкой, отмена fetch. Дополнительно проверены реальная длительность MP3-фреймов против каталога (включая немаркированные 15/30-секундные фрагменты), отказ при неизвестной длительности, атомарная блокировка повторного ENQUEUE / RETRY, синхронизация кнопок страницы, размещение кнопки плеера вне громкости и OAuth callback с проверкой вкладки и state.

Очередь протестирована с настоящими Blob / IndexedDB и реальной библиотекой ZIP; сеть и Chrome Downloads заменены контролируемыми фикстурами. Проверяются содержимое распакованного ZIP, ID3 и ограничение параллельных запросов. Это не выдаётся за скачивание платного трека из пользовательского аккаунта.

Регрессии одиночного скачивания: нажатия в строке и плеере создают одну задачу без диалога и без ZIP; двойное нажатие не создаёт дубль. Фоновый обработчик сохраняет файл прямо в `VOLNA/Треки/`, а движок использует сохранённый номер скачивания в имени (проверен префикс `07 ·`).

Новые проверки сортировки: файлы 07→01 и новый 02, семь песен→08, закрытие пропусков, связанные тексты, пересекающиеся имена, прерванная запись / удаление, восстановление и внешнее изменение файла. Повтор одной задачи не создаёт вторую копию. В отдельном Playwright-сценарии `tests/library-ui-cli.js` выполнены 5 проверок с настоящими браузерными OPFS-дескрипторами, IndexedDB, записью файлов и Web Locks: байты сохраняются, новый номер считается по папке, дескриптор переживает перезагрузку, параллельные вызовы получают разные номера. Системный выбор папки в этом тесте заменён тестовым OPFS-каталогом; доступ к пользовательскому Downloads требует отдельного выбора пользователем.

Дубликат кнопки: воспроизведён старый незавершённый RENDER_METADATA во время повторной инъекции. После завершения старого запроса остаётся ровно один элемент data-volna-player, случайная лишняя копия убирается следующей обработкой DOM.

Защита повторного скачивания проверяется до создания задачи и ещё раз под блокировкой записи папки. Тесты подтверждают: уже сохранённая песня не создаёт новую задачу и не расходует номер; после удаления разрешается скачивание; другой явно выбранный формат доступен отдельно; прежнее короткое MP3-превью не блокирует получение полной версии. Индикатор строки / плеера проверен на совпадение track ID, соседняя песня остаётся без круга, при переключении плеера на другую песню круг исчезает.

22 проверки Playwright CLI: YS-шрифты, пагинация, недоступный FLAC, поиск, Escape и фокус, очередь, отмена и повтор, светлая тема, дополнительные настройки и форма токена, отсутствие донатов, reduced motion и 375 px. Проверены блокировка новой загрузки, круговой прогресс 25%, разблокировка после завершения и блокировка уже открытого диалога при запуске из другого интерфейса. Chrome runtime здесь — тестовая фикстура. Скриншоты лежат в `artifacts/`.

## Реальные сетевые проверки

Без авторизации проверены ответы `api.music.yandex.ru`: метаданные трека, публичного альбома и `tracks/{id}/download-info` — HTTP 200. Проверенный download-info вернул только preview; такой файл VOLNA не экспортирует. Этот ответ позволил подтвердить необходимость отдельного разрешённого полного файла, а также добавить реальный `storage.mds.yandex.net` в список допустимых CDN.

## Пределы проверки

На установленной VOLNA через текущую сессию music.yandex.kz без ручного OAuth получен список «Мне нравится» из 210 композиций. Два файла сохранены через настоящий движок и Chrome Downloads, затем независимо проверены с диска подсчётом MP3-фреймов: Money In The Grave x Her — 183.850 с при каталоге 183.820 с, 7 369 198 байт; Turbo (Majestic) — 175.647 с при каталоге 175.610 с, 7 279 404 байта. Доказательства: `artifacts/live-full-track.json`, `artifacts/live-turbo.json`; воспроизводимая проверка — `scripts/verify-saved.mjs`.

Первоначальная анонимная проверка первых байтов не доказывала полную длительность: сервис выдавал немаркированные фрагменты. Эта ошибка исправлена проверкой длительности до тегирования и экспорта. Старые ранее сохранённые ZIP при этом не меняются.

Не подтверждены для всего каталога: каждый региональный домен и FLAC/OGG/M4A от сервиса. OAuth callback проверен автоматизированно; реальный новый OAuth-grant не создавался, поскольку текущая сессия уже выдала полные файлы. Доступ зависит от прав аккаунта. Собственная WAV-конвертация и ZIP проверены на контролируемых аудиофикстурах.

Figma: макет состоит из редактируемых TEXT, FRAME, INSTANCE, VECTOR, ELLIPSE, а не из скриншота. Шрифтов Яндекса в Figma нет; точное соответствие типографики не прошло проверку и не заявляется. Эталон — локальные PNG и код с YS Text / YS Music.





Очистка: проверены удаление завершённых и осиротевших Blob-записей, сохранение активного staging, границы ID задач, нулевой кэш после успешного ZIP и неудачного сохранения, cache: no-store, защита сортировки от закрытия offscreen при фоновом обслуживании. Разрешение папки после перезагрузки Chrome восстанавливается пользовательским нажатием через requestPermission(), без нового выбора каталога. Пользователь может выбрать постоянный доступ в запросе Chrome (https://developer.chrome.com/blog/persistent-permissions-for-the-file-system-access-api).


## ZIP64 и обработка загрузок, 21 ноября 2026

`npm test`: 112 тестов в 17 файлах. Потоковый писатель обрабатывает почти 10 ГиБ настоящих порций данных через CRC32 и счётный приёмник; запись ограничена 1 МиБ за вызов. Проверены 64-битные смещения после 4 ГиБ, размеры центрального каталога, точная граница лимита вместе с заголовками и отказ при переполнении. Огромный файл на диске не создаётся. Малый ZIP64 распакован fflate и независимым Python zipfile с проверкой CRC и Unicode-имён.

Chrome в изолированном профиле: 22 UI-проверки, 5 проверок настоящих File System Access / IndexedDB / Web Locks; дополнительный ZIP из четырёх файлов по 2 МиБ записан в реальный OPFS, получен как File, скачан браузером, прочитан Python zipfile и побайтно проверен. Временная копия OPFS удалена. Результат: `artifacts/browser-validation.json`. Это не фактическое скачивание 10 ГБ из аккаунта Яндекса; доступная квота и свободное место зависят от браузера и диска. Тестовый ZIP 8 МиБ удалён после проверки.

Движок проверен на отмену, ошибку сохранения и нехватку квоты с удалением временных файлов. Метаданные трёх песен получают один запрос; общая обложка для трёх параллельных песен и архива запрашивается один раз. Проверено настоящее перекрытие двух передач и исправлена потеря WAKE при постановке новой задачи во время завершения очистки. Измерения реальной скорости CDN не проводились.

Сборка выполняется в новом каталоге `C:\Users\Akerke\Desktop\YandexExtension\volna`. Установленная копия Chrome в этой сессии не обновлялась автоматически.


## Потоки и завершение ZIP

Выбор 1–5 потоков доступен в диалогах страницы и popup; новый профиль получает 3 потока по умолчанию, сохранённый выбор остаётся. Надпись о 10 ГБ убрана из интерфейса ZIP. Контент-тест проверяет передачу выбранного значения 5 в ENQUEUE, браузерный тест проверяет его в задании.

Детерминированные проверки: 7 треков успешно сохранены при пике 5 одновременных передач; 500 событий прогресса пяти передач объединяются в один пакет; завершение 5000 треков занимает одну запись chrome.storage.local. Завершённый трек не получает устаревшие байты прогресса. Метаданные пакета тоже сохраняются одной записью. Убраны пустые IndexedDB get/delete для каждого ZIP-трека и пофайловая очистка при отмене/очистке истории.

Передача не обрывается по общей длительности 180 секунд. Таймер сбрасывается при получении данных и срабатывает при отсутствии ответа 45 секунд. С искусственными часами проверены 320 секунд непрерывного поступления данных, настоящий простой и немедленная пользовательская отмена. Это проверка логики, не измерение скорости CDN и не воспроизведение конкретной ошибки пользователя на полном плейлисте.


Итоговое устройство сетевых очередей, статистика скорости/ETA, проверки native Range и ограничения браузера описаны в NETWORK_OPTIMIZATION.md. Последний полный прогон: 112 тестов в 17 файлах, 22 UI-проверки, 5 FSA-проверок; native HTTP-проверка подтвердила SHA-256 всех файлов после обрыва, смены зеркала и многосегментной сборки. Плеер Яндекса сохранён.
